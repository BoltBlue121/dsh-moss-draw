# 02 · 部署流程

从零到能画第一张图的完整步骤。默认在 `<repo>` 下用 Windows PowerShell 执行；脚本同时兼容 Windows PowerShell 5.1 与 PowerShell 7（脚本头声明 `#Requires -Version 5.1`，不使用 `??`、`-Parallel` 等 PS7 专有语法）。

本文用四个占位符：`<repo>` 表示仓库根目录，`<DshHome>` 表示 DSH home（默认 `%USERPROFILE%\.dsh`），`<workspaceRoot>` 表示允许插件读图的绝对目录，`<comfy-host>` 表示 ComfyUI 的主机名或地址。

## 0. 备份与前置

1. **正常退出 DSH Desktop**（菜单退出，不要强杀 Host 进程）。安装脚本不会重启 DSH，也不会启动第二个实例；但正在运行的 Host 会占用 profile 目录，先退出最省事。
2. **确认版本**：DSH Desktop 必须是 `0.2.1-rc.2` / `0.2.1-rc.3` / `0.2.1-rc.5`。矩阵外版本走第 1 步探测会得到退出码 `2`。
3. **确认路径**：`<DshHome>` 是含 `profiles\` 的目录。默认桌面安装是 `%USERPROFILE%\.dsh`（由首次启动 DSH Desktop 创建）；如果部署方自定义过，用显式 `-DshHome` 传入。`probe.mjs` 省略 `--dsh-home` 时会退回读 `DSH_HOME` 环境变量，两者不一致时以命令行参数为准。
4. **准备 ComfyUI**：已启动，Host 进程可直连，模型与节点按 [01-适配清单.md](01-适配清单.md) 第 3 节就位。
5. **准备资料**：`<workspaceRoot>` 已存在；`<dataRoot>` 建议选 `<workspaceRoot>` 之外的私有目录。
6. **执行策略**：脚本被拦截时，在**当前窗口**放行，不改机器级配置：

   ```powershell
   Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
   ```

   从下载的 zip 解包可能给文件打上 Mark-of-the-Web，可对脚本与 kit 解包目录解除锁定：

   ```powershell
   Get-ChildItem -Recurse -File | Unblock-File
   ```

7. **安装脚本自带的备份**：下一步正式安装时，脚本会先把 profile 的 `package.json`、profile 的 `cordis.patch.yml`（若存在）、`probe.json`、旧安装根与适配回执写入 `<DshHome>\system\backups\portable-moss-draw-<yyyyMMdd-HHmmss>\`。额外的机器级备份仍建议自己做一份。

## 1. 探测（probe）

`probe.mjs` 读取 `resources\app.asar` 里的 DSH 包与 SDK，只有 Electron 的 Node 模式能读该归档，所以必须通过官方 `DeepSeek Harness.exe` 运行：

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
& "$env:LOCALAPPDATA\Programs\DeepSeek Harness\DeepSeek Harness.exe" `
  .\install\probe.mjs `
  --desktop-dir "$env:LOCALAPPDATA\Programs\DeepSeek Harness" `
  --dsh-home "$env:USERPROFILE\.dsh" `
  --json
```

参数：`--desktop-dir`、`--dsh-home`、`--profile`（默认 `desktop`）、`--json`、`--out <file>`、`--allow-unverified-version`。省略 `--dsh-home` 时读 `DSH_HOME` 环境变量。

退出码与判定：

| 退出码 | `decision` | 含义 |
|---|---|---|
| `0` | `supported` | 版本在已验证矩阵内 |
| `0` | `unverified-override` | 传了 `--allow-unverified-version`；此后只能标注 experimental |
| `2` | `refused` | 版本在矩阵外，未豁免；安装脚本以 `2` 退出 |
| `1` | — | 探测失败（二进制/`app.asar`/SDK 读不到，或参数错误） |

先看这几项：`dshPackage.version`、`checks.node24`、`checks.sdkResolved`、`profile.pluginDependency`、`profile.pluginBundleListed`。探测通过只说明「这台机器的 DSH 与 SDK 结构可加载插件」，不证明画质，也不提交任何 GPU 任务。

## 2. 参数

| 参数 | 必填 | 默认 | 取值要点 |
|---|---|---|---|
| `-DshHome` | 是 | 无 | 含 `profiles\` 的目录；默认桌面安装是 `%USERPROFILE%\.dsh` |
| `-WorkspaceRoot` | 是 | 无 | 绝对路径，必须已存在；插件只读这个根内的图片 |
| `-ComfyUrl` | 是 | 无 | 裸 origin，如 `http://127.0.0.1:8188`；不带 path/query/hash/userinfo |
| `-Profile` | 否 | `desktop` | profile 目录名 |
| `-DataRoot` | 否 | `<workspaceRoot>\private\workspace\moss-draw` | 绝对路径 |
| `-DesktopDir` | 否 | `%LOCALAPPDATA%\Programs\DeepSeek Harness` | 官方 Desktop 目录；也可用 `DSH_DESKTOP_DIR` |
| `-InstallRoot` | 否 | `<DshHome>\plugins\dsh-moss-draw` | 插件源码副本落地位置 |
| `-NodeExe` | 否 | 官方 Desktop 可执行文件 | 仅用于 `adapt.mjs`；探测始终走 Desktop 二进制 |
| `-Force` | 否 | 关 | 备份后替换已存在的安装根或真实目录链接 |
| `-AllowUnverifiedVersion` | 否 | 关 | 矩阵外版本继续安装，只能标注 experimental |
| `-DryRun` | 否 | 关 | 只打印计划，不改文件 |

把一个真实值记进部署记录（第 11 节），不要只在命令行里留一次。

## 3. 演练（`-DryRun`）

```powershell
.\install\install.ps1 `
  -DshHome "$env:USERPROFILE\.dsh" `
  -WorkspaceRoot 'D:\work' `
  -ComfyUrl 'http://127.0.0.1:8188' `
  -DryRun
```

演练阶段会做真实校验（`DshHome`、profile、Desktop 二进制、探测），但不创建备份目录、不拷贝、不改 profile、不建链接。配置写入以 `adapt.mjs --dry-run` 校验 kit 里那份原始 `plugin\cordis.patch.yml`，回执写到临时目录。输出里应能看到：探测结果、`would back up ...`、`would copy ...`、`would link ...`、`would add dependency ...`、`would append ... to dsh.profile.bundles`。

## 4. 正式安装

去掉 `-DryRun` 重跑同一条命令。脚本按固定顺序执行：

1. **校验**：`DshHome`、profile `package.json`（含 `dsh.profile`）、kit 的 `plugin\`、`adapt.mjs`、`probe.mjs`、Desktop 二进制。
2. **探测**：以 `ELECTRON_RUN_AS_NODE=1` 运行 `install/probe.mjs`；失败按退出码 `2` / `3` 中止。
3. **备份**：`<DshHome>\system\backups\portable-moss-draw-<yyyyMMdd-HHmmss>\`，含 profile `package.json`、profile `cordis.patch.yml`（若存在）、`probe.json`、旧安装根（若存在）、后续的 `adapt-receipt.json`。
4. **拷贝**：`robocopy plugin\ <InstallRoot>`（`/E`，退出码 ≥8 视为失败）。
5. **写配置**：`adapt.mjs` 把三个占位符替换成真实值，写入 `<InstallRoot>\cordis.patch.yml`。
6. **建链接**：`<profile>\node_modules\@dsh-external\dsh-moss-draw` → `<InstallRoot>` 的 junction。
7. **登记**：profile `package.json` 的 `dependencies["@dsh-external/dsh-moss-draw"] = "link:<InstallRoot 正斜杠形式>"`，并把包名追加到 `dsh.profile.bundles`。

退出码：

| 码 | 含义 | 处理 |
|---|---|---|
| `0` | 成功 | 进入第 5 步 |
| `2` | 版本在已验证矩阵外 | 先升级/回退 DSH，或明确用 `-AllowUnverifiedVersion` 标注 experimental |
| `3` | 参数或探测失败 | 按报错修路径/参数；探测报告在临时目录，报错行会给出路径 |
| `4` | 拷贝或写配置失败 | 检查文件占用、杀软、磁盘；占位符已适配过时需重拷原始 `plugin\` |
| `5` | 链接失败（目标位置是真实目录且未给 `-Force`，或 junction 创建失败） | 确认目录内容后用 `-Force` 备份并替换；创建失败时检查路径权限 |
| `6` | profile 缺 `dsh.profile` | `-DshHome`/`-Profile` 指错了目录 |

## 5. 重启 DSH

正常退出并重新启动 DSH Desktop。**只刷新 GUI 不会加载新的 Host 代码**；脚本从不自行重启 DSH，也不要强杀 Host。重启后 Host 才读取 `<InstallRoot>\cordis.patch.yml` 与 profile 的 bundle 列表。

## 6. 新会话、预设、模型渠道

1. 新建空白会话（不要复用旧会话；旧会话的历史里没有这套工具上下文）。
2. Agent preset 选「AI 画画」（id `ai-draw`）。
3. 在原生模型栏选择一个**能看图**的模型渠道：写稿、审图与工作台预览都依赖模型读图；插件不提供渠道，也不存 Key。
4. 先发一句低成本请求确认链路：「先读 `art_guide quick`，然后列出你注册的 7 个 `art_*` 工具名称」。预期返回 quick 页文本与 7 个工具名，这一步不需要 GPU。

## 7. 工作台冒烟

1. 右侧栏应出现「AI画画工作台」页签；对话区还会多一个「MOSS工作台」视图。
2. 在工作台新建一个系列 → 新建一页 → 修改标题或 caption，确认能保存（`revision` 递增）。
3. 断言不需要 GPU 的部分：Layout 画布、区域框、相机参数、提案/采纳、文档读取（`art_context({document_id})`）。
4. 只有部署方明确授权时，才让 Agent 提交真实 GPU 任务；这属于人工决定，不是安装步骤。

冒烟的判定标准与「验证脚本不覆盖什么」见 [03-验证与验收.md](03-验证与验收.md)。

## 8. 失败对照表

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 脚本无法运行，提示不允许执行脚本 | 执行策略 | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`，或 `Unblock-File` |
| 安装脚本退出 `2` | DSH 版本在矩阵外 | 升级/回退到 rc.2 / rc.3 / rc.5，或 `-AllowUnverifiedVersion` 并标注 experimental |
| 退出 `3`，`Desktop executable not found` | `-DesktopDir` 不对 | 传 `-DesktopDir` 或设 `DSH_DESKTOP_DIR` |
| 退出 `3`，`workspaceRoot does not exist` | 目录未创建 | 先创建 `<workspaceRoot>`；确实稍后挂载时用 `adapt.mjs --allow-missing-workspace` |
| 退出 `4`，`robocopy failed` | 文件被占用/杀软拦截 | 退出 DSH 与编辑器，重试；必要时换 `-InstallRoot` |
| 退出 `4`，`cordis.patch.yml has no __MOSS_*__ placeholders` | 该目录已被适配过 | 重新拷贝原始 `plugin\` 后再适配 |
| 退出 `5` | 链接位置是真实目录 | 确认内容后用 `-Force`（会先备份） |
| 退出 `6` | profile `package.json` 没有 `dsh.profile` | 检查 `-DshHome` 与 `-Profile` |
| 重启后没有「AI 画画」预设 | `dsh.profile.bundles` 没登记 / junction 断了 / 占位符未替换 | 看 Host 日志；核对 [01-适配清单.md](01-适配清单.md) 第 5 节字段 |
| Host 报 `MOSS_CONFIG_WORKSPACE` | `workspaceRoot` 不是绝对路径 | 重跑 `adapt.mjs`，传绝对路径 |
| Host 报 `MOSS_CONFIG_COMFY_URL` | URL 带 path/query/userinfo，或不是 http(s) | 改成裸 origin |
| Host 报 `MOSS_CONFIG_DATA_ROOT` | `dataRoot` 不是绝对路径 | 重跑 `adapt.mjs` |
| Host 报 `MOSS_CONFIG_EDIT_ENGINE` | `editEngine` 不是 `native`/`legacy` | 改成两者之一或删掉该项 |
| 预设可选但工具不出现 | 还在旧会话里，或会话没套用该预设 | 新建空白会话，重选「AI 画画」 |
| `MOSS_IMAGE_NOT_VISIBLE` | 图片不在 `<workspaceRoot>` 内，或本条消息没点名该路径 | 把路径写进消息（含空格时用引号/尖括号/反引号） |
| run 报 `NETWORK_UNKNOWN` | ComfyUI 不可达、超时或返回被中断 | 检查 Host 到 `<comfy-host>` 的连通性；查询同一 run，不要重提 |
| run 报 `REDIRECT_BLOCKED` | ComfyUI 前面有会跳转的网关 | 直连 origin |
| run 报 `UNSAFE_OUTPUT` / `INVALID_ARTIFACT` | worker 输出的不是 PNG 或路径不安全 | 检查 ComfyUI 的 `SaveImage` 输出 |
| 提交后很快失败 | 模型文件缺失、`class_type` 不存在、CLIP `type` 不匹配 | 对照 [01-适配清单.md](01-适配清单.md) 第 3 节 |
| `STUDIO_TASK_BINDING_REQUIRED` / `STUDIO_TEXT_ONLY` | 工作台里还有未结算任务或处于纯文本授权模式 | 在工作台结算/退出该模式，不要靠换页面绕过 |

## 9. 安装脚本的回滚

```powershell
# 默认使用 <DshHome>\system\backups 下最新的 portable-moss-draw-* 备份
.\install\rollback.ps1 -DshHome "$env:USERPROFILE\.dsh"

# 指定备份，并顺带把安装根移走
.\install\rollback.ps1 `
  -DshHome "$env:USERPROFILE\.dsh" `
  -BackupDir "$env:USERPROFILE\.dsh\system\backups\portable-moss-draw-20261031-120000" `
  -RemoveInstallRoot
```

`rollback.ps1` 做的事：先把当前 profile 的 `package.json` / `cordis.patch.yml` 复制到备份目录下的 `rollback-before-<stamp>\`（安全副本），再恢复备份里的 `package.json`；备份里有 `cordis.patch.yml` 时一并恢复；移除 profile 的 junction；带 `-RemoveInstallRoot` 时把活动安装根移进安全副本目录。**它从不删除数据根**，工作台 SQLite 与生成图都保留。

退出码：`0` 成功；`3` 参数错误或找不到备份；`5` 期望移除 junction 但遇到真实目录且未给 `-Force`。

回滚的语义要点：

- 恢复的是**上一次安装之前**的 profile 状态，不是「完整卸载」：它不会删除数据根、不会清理 ComfyUI 侧任何东西，也不会撤销你在市场 UI 里做过的其它插件操作。
- 重装/升级场景下，回滚只会回到**最后一次**安装前的快照；更早的历史仍在各自的 `portable-moss-draw-*` 备份目录里，需要显式 `-BackupDir`。
- 恢复后正常重启 DSH，「AI 画画」预设应消失；若官方插件管理器仍列出该插件，在那里停用/移除。
- 保留安装根时可以直接再跑 `install.ps1` 重装。

## 10. 备选路径：tgz 与手工等价安装

<a id="install-verified-bundle"></a>

### 10.1 校验、适配和链接发行包

从同一 Release 下载源码 zip 和三个附件。把 `dsh-external-dsh-moss-draw-0.9.0.tgz`、`SHA256SUMS.txt` 和 `package-manifest.json` 放进源码的 `dist`，在源码根目录打开 PowerShell。下面的命令校验收到的压缩包。运行 `build-package.mjs` 会重新打包。

```powershell
$tgz = (Resolve-Path '.\dist\dsh-external-dsh-moss-draw-0.9.0.tgz').Path
$desktopDir = Join-Path $env:LOCALAPPDATA 'Programs\DeepSeek Harness'
$desktopExe = Join-Path $desktopDir 'DeepSeek Harness.exe'
$stage = Read-Host '新版本的长期安装目录（绝对路径）'
if (-not [IO.Path]::IsPathRooted($stage) -or (Test-Path -LiteralPath $stage)) { throw '请填写尚不存在的绝对目录' }
$workspaceRoot = (Resolve-Path -LiteralPath (Read-Host '已有作品根目录')).Path
$dataRoot = Read-Host '数据根目录的绝对路径，升级请填原值'
$comfyUrl = Read-Host 'ComfyUI 的 origin，含协议和端口'
$oldNodeMode = $env:ELECTRON_RUN_AS_NODE
try {
  $env:ELECTRON_RUN_AS_NODE = '1'
  & $desktopExe .\verify\verify-package.mjs --kit . --tgz $tgz | Out-Host
  if ($LASTEXITCODE -ne 0) { throw '发行包校验失败' }
  New-Item -ItemType Directory -Path $stage -ErrorAction Stop | Out-Null
  tar.exe -xzf $tgz -C $stage
  if ($LASTEXITCODE -ne 0) { throw '解包失败' }
  & $desktopExe .\verify\verify-package.mjs --kit . --tgz $tgz --extract $stage | Out-Host
  if ($LASTEXITCODE -ne 0) { throw '解包内容与发行清单不同' }
  $packageDir = Join-Path $stage 'package'
  & $desktopExe .\install\adapt.mjs --plugin-dir $packageDir --workspace-root $workspaceRoot --comfy-url $comfyUrl --data-root $dataRoot | Out-Host
  if ($LASTEXITCODE -ne 0) { throw '适配失败' }
} finally { $env:ELECTRON_RUN_AS_NODE = $oldNodeMode }
$spec = 'link:' + (Resolve-Path -LiteralPath $packageDir).Path.Replace('\','/')
```

首次安装时，用官方 Plugin Manager 添加 `$spec` 并启用。保留适配目录，核对 profile 的依赖指向该目录、bundle 列表已选择 `@dsh-external/dsh-moss-draw`，再用新会话打开「AI画画工作台」。

已有同名插件时，保留原目录和配置，并备份作品库。rc.3 的运行中宿主会拒绝同名热替换。维护窗口内完全退出 Desktop，确保没有其他程序写入该 profile。以下命令用 Desktop 自带的插件管理 CLI，切换已经启用的 bundle。先将 `DSH_HOME` 设为实际包含 `profiles\desktop` 的目录。

```powershell
$desktopCli = Join-Path $desktopDir 'resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js'
if (-not $env:DSH_HOME -or -not (Test-Path -LiteralPath (Join-Path $env:DSH_HOME 'profiles\desktop\package.json'))) { throw '请核对 DSH_HOME' }
if (Get-Process -Name 'DeepSeek Harness' -ErrorAction SilentlyContinue) { throw '请先完全退出 Desktop' }
$oldNodeMode = $env:ELECTRON_RUN_AS_NODE
try {
  $env:ELECTRON_RUN_AS_NODE = '1'
  & $desktopExe --expose-internals $desktopCli plugin --profile desktop add --offline --ignore-scripts $spec | Out-Host
  if ($LASTEXITCODE -ne 0) { throw '插件管理器未完成切换' }
} finally { $env:ELECTRON_RUN_AS_NODE = $oldNodeMode }
```

重新启动后，从新会话核对版本、worker 连接和旧作品。若需回滚，完全退出 Desktop，在维护窗口把 `$spec` 指回保留的旧版适配目录，再执行同一链接命令。通过 `install.ps1` 安装产生的备份，使用其配套的 `rollback.ps1`。

### 10.2 手工等价安装（不使用 install.ps1）

依次手做脚本的四步，任何一步都不能省：

1. 把 `plugin\` 完整复制到 `<InstallRoot>`；
2. 用 `adapt.mjs` 适配 `<InstallRoot>\cordis.patch.yml`；
3. 在 profile 建 junction：`New-Item -ItemType Junction -Path "<profile>\node_modules\@dsh-external\dsh-moss-draw" -Target "<InstallRoot>"`；
4. 修改 `<profile>\package.json`：

```json
{
  "dependencies": {
    "@dsh-external/dsh-moss-draw": "link:D:/.../plugins/dsh-moss-draw"
  },
  "dsh": {
    "profile": {
      "bundles": ["@dsh-external/dsh-moss-draw"]
    }
  }
}
```

`bundles` 与 `dependencies` 里可能已有其它条目，追加时保留原有内容，不要把数组或对象整体替换掉。

改完正常重启 DSH，并用第 1 节的 `probe.mjs` 复核 `pluginDependency`、`pluginBundleListed` 与 `installedVersion`。
