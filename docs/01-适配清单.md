# 01 · 适配清单

部署前逐项核对。本清单描述**部署方必须提供什么**、**插件期望在 ComfyUI 与 profile 里看到什么**。任一项不满足就先解决，不要跳步安装。

本文用四个占位符：`<repo>` 表示仓库根目录，`<DshHome>` 表示 DSH home（默认 `%USERPROFILE%\.dsh`），`<workspaceRoot>` 表示允许插件读图的绝对目录，`<comfy-host>` 表示 ComfyUI 的主机名或地址。

## 1. 部署方必须提供

| 项 | 要求 | 不满足的后果 |
|---|---|---|
| DSH Desktop | `0.2.1-rc.2` / `0.2.1-rc.3` / `0.2.1-rc.5`（Windows，node 24.21.0、pnpm 11.28.5、Electron 44.x） | 矩阵外版本 `probe.mjs` 退出码 `2`，`decision=refused` |
| `<DshHome>` | 已存在且含 `profiles\<profile>\package.json`；默认桌面安装为 `%USERPROFILE%\.dsh`，由首次启动 DSH Desktop 创建 | 安装脚本退出码 `3`；profile 缺 `dsh.profile` 时退出码 `6` |
| `<workspaceRoot>` | **已存在**的绝对路径。插件只读取该根内、且在消息里被点名过的图片 | `adapt.mjs` 拒绝写入；Host 报 `MOSS_CONFIG_WORKSPACE` |
| ComfyUI origin | 裸 `http://` / `https://` origin，例如 `http://127.0.0.1:8188`；**从 DSH Host 进程可达** | Host 报 `MOSS_CONFIG_COMFY_URL`，或 run 报 `NETWORK_UNKNOWN` |
| `<dataRoot>` | 绝对路径（可不存在，首次写入时创建）；建议放在 `<workspaceRoot>` 之外的私有目录 | Host 报 `MOSS_CONFIG_DATA_ROOT` |
| 模型与自定义节点 | 见第 3 节；插件不附带任何权重 | 提交阶段失败（ComfyUI 侧节点/模型缺失，Host 侧报 `INVALID_RESPONSE` 等） |
| 模型渠道 | 原生模型栏里一个**能看图**的模型渠道；插件不存 Key | 预设能加载，但写稿/审图链路无法完成 |

## 2. ComfyUI 侧要求

- **地址形态**：origin 不能带 path、query、hash 或 userinfo；`http://user:pass@host:8188` 会被直接拒绝。需要鉴权时请在网络层处理，不要写进 URL。
- **可达性**：请求由 DSH **Host** 进程发出，不是浏览器。ComfyUI 在本机或内网均可，但必须让 Host 进程直连可达；`127.0.0.1` 表示 Host 所在机器自己。
- **用到的 HTTP 接口**：`POST /upload/image`（上传参考图）、`POST /prompt`（提交图）、`GET /history/<prompt_id>`、`GET /queue`、`GET /view?filename=...`（取结果 PNG）。不需要 `/object_info`。
- **重定向**：任何 3xx 都被视为 `REDIRECT_BLOCKED`；不要把 ComfyUI 挂在会跳转的网关后面。
- **输出约定**：结果必须是 `type=output` 的 `.png`，文件名/子目录来自 ComfyUI 自身；`moss_draw/<runId>/...` 前缀由插件写入图。
- **采样枚举**：t2i 的 `sampler` / `scheduler` 白名单在插件内冻结；worker 的 `KSampler` 必须支持所选集。不在白名单的名字在插件侧就会被拒绝，不会发到 worker。
- **队列与并发**：一个 run 对应一次提交；超时只查询同一 run。部署方需自行保证 ComfyUI 的显存/队列策略不会把任务排到超时。

## 3. 模型与节点清单

下表按模板与适配器里实际引用的 `class_type` 与文件名整理。文件位置按 ComfyUI 惯例（`models/unet` 或 `models/diffusion_models`、`models/text_encoders`、`models/vae`、`models/loras`），以部署方 ComfyUI 版本的实际目录名为准。**`class_type` 是否存在以该 ComfyUI 的节点列表为准**；本表只说明插件会提交哪些类名，不代替部署方核对。

### 3.1 MOSS t2i（`backend` moss，`mode` t2i）

| 类别 | 内容 |
|---|---|
| UNet | `moss_image_base_int8_convrot.safetensors`（`model=base`）或 `moss_image_sft_int8_convrot.safetensors`（`model=sft`） |
| CLIP | `qwen3.5_9b_w4a8_gptq.safetensors`，`CLIPLoader` 的 `type` 必须是 `moss_image` |
| VAE | `flux2-vae_small.safetensors` |
| LoRA | 内置无（`style` 只有 `none`，`lora_strength` 必须 0）；调用方自备的 `loras` 走 `LoraLoaderModelOnly` |
| class_type | `UNETLoader`、`CLIPLoader`、`VAELoader`、`ModelSamplingAuraFlow`、`SkipLayerGuidanceDiTSimple`、`CLIPTextEncode`、`EmptyFlux2LatentImage`、`KSampler`、`VAEDecode`、`SaveImage`、`LoraLoaderModelOnly`（有 `loras` 时） |

尺寸约束：16 对齐，`width` ≤ 2048（另有恰好 2560×1440 一档），`width*height` ≤ 2.1 MP。

### 3.2 MOSS native edit（`backend` moss，`mode` edit，`editEngine=native`，默认）

| 类别 | 内容 |
|---|---|
| UNet | `moss_image_sft_int8_convrot.safetensors`（固定 `model=sft`） |
| CLIP | `qwen3.5_9b_w4a8_gptq.safetensors`（`type=moss_image`） |
| VAE | `flux2-vae_small.safetensors` |
| LoRA | 编辑 adapter `MOSS-Image-Edit-rank64.safetensors`，必须位于 ComfyUI 的 `loras/` 下（模板固定引用该文件名） |
| class_type | `UNETLoader`、`CLIPLoader`、`VAELoader`、`LoraLoaderModelOnly`、`ModelSamplingAuraFlow`、`TextEncodeMOSSImageEdit`、`ImageScale`、`EmptyFlux2LatentImage`、`KSampler`、`VAEDecode`、`SaveImage`、`LoadImage` |

参考图 1–4 张，每张缩放到最长边 512；输出 16 对齐、≤2.1 MP。单参考是已验证路径，多参考身份/布局一致仍属 experimental。

### 3.3 MOSS legacy edit（`editEngine=legacy`）

| 类别 | 内容 |
|---|---|
| 模型目录 | 模板引用 `snapshot_dir: moss_image/MOSS-Image-SFT` 与 `adapter_dir: moss_image/Moss-Image-Edit` |
| class_type | `MossImageEditLoader`、`MossImageEdit`、`LoadImage`、`SaveImage`（1–4 张参考用 `edit-single` / `edit-multi` 模板） |
| 何时使用 | 只有部署方 ComfyUI 核心缺少 native edit 节点时才考虑；默认不是它 |

### 3.4 inpaint（`mode` inpaint）

| 类别 | 内容 |
|---|---|
| 输入 | 唯一一张 RGBA PNG：alpha=0 可编辑、alpha=255 保留；必须同时含两类像素 |
| 模型 | `moss_image_sft_int8_convrot.safetensors` + 同一 CLIP/VAE |
| class_type | `UNETLoader`、`CLIPLoader`、`VAELoader`、`DifferentialDiffusion`、`LoadImage`、`PrimitiveStringMultiline`、`CLIPTextEncode`、`GrowMaskWithBlur`、`MaskBoundingBox+`、`ImageScaleToTotalPixels`、`VAEEncode`、`SetLatentNoiseMask`、`KSampler`、`VAEDecode`、`ImageScale`、`ImageCompositeMasked`、`MaskToImage`、`PreviewImage`、`SaveImage` |

输出保持原图尺寸；`steps` 默认 25、`cfg` 默认 2.5、`sampler=er_sde`、`scheduler=simple`（固定）。

### 3.5 characters（`mode` characters，1–2 个角色）

| 类别 | 内容 |
|---|---|
| 模型 | `moss_image_sft_int8_convrot.safetensors` + 同一 CLIP/VAE；不使用参考图 |
| class_type | 多角色节点 `RSMultiCharacterPrompt`、`RSMultiCharacterLoRA`、`RSMultiCharacterPosition`、`RSMultiCharacterFinalize`、`RSMultiCharacterSampler`，以及 `PrimitiveStringMultiline`、`UNETLoader`、`CLIPLoader`、`VAELoader`、`SaveImage` |
| 说明 | 每个角色带 `prompt` 与归一化 `x`/`y`；角色 LoRA 固定 `None`、强度 0。多人画面质量必须逐图审 |

### 3.6 regions（`mode` regions，1–4 个区域）

区域执行不是单独一套模型：它把画布裁块后逐区调用编辑引擎，再合成回画布。

| 类别 | 内容 |
|---|---|
| 画布参考 | 第 1 张参考必须是 PNG 画布（≤4.5 MP）；其后 1–3 张为角色参考，每张 ≤2.1 MP（总参考数 2–4） |
| 每区执行 | 默认走 native edit（3.2 的模型与节点）；`editEngine=legacy` 时走 3.3 |
| 可选 Qwen 修复 | 区域级 `qwen_prompt` 或整图 `qwen_full_prompt` 需要 3.8 的节点与权重 |
| class_type | 同 3.2 / 3.3；带 Qwen 时同 3.8 |
| 语义 | `box` 是原图半开像素区间 `[left,top,right,bottom)`；区域按列表顺序合成，**后一个覆盖前一个**；无整图 Qwen 时区外像素被逐点校验不得改变；有整图 Qwen 时区外不再保证 |

### 3.7 K2 / Krea2 t2i（`backend` k2，`mode` t2i）

| 类别 | 内容 |
|---|---|
| UNet | `krea2_turbo_fp8_scaled.safetensors` |
| CLIP | `qwen3vl_4b_fp8_scaled.safetensors`，`CLIPLoader` 的 `type` 必须是 `krea2` |
| VAE | `qwen_image_vae.safetensors` |
| LoRA | 内置无（`style=none`、`lora_strength=0`）；调用方自备 `loras` 走 `LoraLoaderModelOnly` |
| class_type | `UNETLoader`、`CLIPLoader`、`VAELoader`、`CLIPTextEncode`、`ConditioningZeroOut`、`EmptyLatentImage`、`KSampler`、`VAEDecode`、`SaveImage`、`LoraLoaderModelOnly`（有 `loras` 时） |

固定 `steps` 8–20（默认 8）、`cfg=1`、`sampler=euler`、`scheduler=simple`；尺寸 32 对齐、≤2560×1536，大画幅只接受 `2048×1536`、`2560×1440`、`2560×1536`。

### 3.8 Qwen-Image-2.1 edit（`backend` qwen，`mode` edit）

| 类别 | 内容 |
|---|---|
| UNet | `qwen_image_2.1_turbo_int8_convrot.safetensors` |
| CLIP | `qwen3vl_8b_int8_convrot.safetensors`，`CLIPLoader` 的 `type` 必须是 `qwen_image` |
| VAE | `qwen_image_2.1_vae_bf16.safetensors` |
| class_type | `UNETLoader`、`CLIPLoader`、`VAELoader`、`LoadImage`、`TextEncodeQwenImageEditPlus`、`ConditioningZeroOut`、`EmptyLatentImage`、`KSamplerSelect`、`ManualSigmas`、`SamplerCustom`、`VAEDecode`、`SaveImage` |
| 契约 | 1–2 张参考；固定 `steps=8`、`cfg=1`；默认继承第一张参考的像素尺寸；不接受 `negative`、不接受 `loras`。整图编辑，区外像素与透明背景都不保证 |

### 3.9 自加画风 LoRA（可选，二次开发）

仓库不附带任何画风 LoRA，`style` 枚举只有 `none`。部署方若要固定画风，需要自己改 `src/catalog.mjs` 的 `STYLES`、相关模式列表与模板，属于二次开发，不在本包支持与验收范围。`worker/moss-draw-style/` 提供的 `MossDrawEditStyleLoader` 只在旧式（legacy）编辑链里 merge 画风 LoRA，默认 native 链不引用它；装与不装都不影响默认生成。

## 4. 目录与权限规则

- **`workspaceRoot` 是唯一读图根**：`art_view` 的 `path` 与 `art_generate` 的 `references` 只能是该根内的文件，且必须是本会话消息里用户点名过的路径（或本会话 run 的 `run:<UUID>`）。解析走 `realpath`，符号链接不能越界；不存在的、越界的、非图片格式的路径一律报 `MOSS_IMAGE_NOT_VISIBLE`。
- **路径含空格或中文**：消息里用引号、尖括号或反引号包起来，否则不会被识别为用户已提供该文件。
- **`dataRoot`**：必须是绝对路径。工作台 SQLite、会话账本、run 记录、生成图都在这里；插件不写安装目录，也不扫描其它会话的目录。
- **安装目录**：`plugin\` 会被复制到 `<InstallRoot>`（默认 `<DshHome>\plugins\dsh-moss-draw`），配置文件是 `<InstallRoot>\cordis.patch.yml`。不要手工改包内 `plugin\` 再期望已安装副本变化。
- **profile 链接**：`<profile>\node_modules\@dsh-external\dsh-moss-draw` 是指向 `<InstallRoot>` 的 junction；profile 的 `package.json` 里 `dependencies` 记 `link:<InstallRoot 正斜杠形式>`，并在 `dsh.profile.bundles` 追加包名。

## 5. profile 与 bundle 注册怎么核对

安装后可读 `install/probe.mjs` 的报告（或 `<DshHome>\system\backups\portable-moss-draw-*\probe.json`）确认：

| 字段 | 期望 |
|---|---|
| `dshPackage.version` | 在 `0.2.1-rc.2` / `rc.3` / `rc.5` 之内 |
| `checks.node24` | `true` |
| `checks.sdkResolved` | `true`（12 个 SDK 包，含 `cordis` 与 `schemastery`，全部解析） |
| `profile.pluginDependency` | `link:<InstallRoot>` |
| `profile.pluginBundleListed` | `true` |
| `profile.installedVersion` | `0.8.0` |
| `decision` | `supported` |

`dsh.profile.bundles` 里缺包名时 Host 不会加载这个 bundle；`dependencies` 里缺 `link:` 时 pnpm 解析不到包。两者都由 `install.ps1` 写入，路径 B/C 需要手工补。

| DSH Desktop | 结论 |

## 7. 安装前勾选清单

- [ ] DSH Desktop 版本在矩阵内，且 `probe.mjs` 能从 `resources\app.asar` 读到 SDK。
- [ ] `<DshHome>\profiles\desktop\package.json` 存在且有 `dsh.profile` 段。
- [ ] `<workspaceRoot>` 是**已存在**的绝对路径，里面放的是部署方自己的工作区。
- [ ] ComfyUI 已在 `<comfy-host>:<port>` 运行，Host 进程可直连，origin 不含 path/query/userinfo。
- [ ] 3.1–3.8 中要用到的模型文件已放进 ComfyUI 对应目录，文件名与表一致。
- [ ] `moss_image_sft_int8_convrot.safetensors` 与 `MOSS-Image-Edit-rank64.safetensors`（native edit）就位。
- [ ] 要用 edit / regions 时，`TextEncodeMOSSImageEdit` 与 native edit 其它 `class_type` 在该 ComfyUI 上存在。
- [ ] 要用 characters 时，`RSMultiCharacter*` 五个节点存在。
- [ ] 要用 inpaint 时，`MaskBoundingBox+`、`GrowMaskWithBlur` 等模板节点存在。
- [ ] 要用 Qwen 时，`TextEncodeQwenImageEditPlus`、`ManualSigmas`、`SamplerCustom` 存在。
- [ ] 覆盖安装或升级前，确认 `<DshHome>\system\backups\portable-moss-draw-*` 可写（脚本会在这里留备份）。
- [ ] 已阅读 [02-部署流程.md](02-部署流程.md)，并准备先跑一次 `-DryRun`。
- [ ] 若从下载的 zip 解包，已 `Unblock-File`（Mark-of-the-Web）或准备好临时放开执行策略。

## 8. 本仓库不提供的内容

- 模型权重：MOSS base/sft、MOSS Edit adapter、K2（Krea2）、Qwen-Image-2.1 的 UNet / CLIP / VAE 全都不带。
- 任何 LoRA 权重，包括画风 LoRA；`style` 只有 `none`。
- ComfyUI 本体、自定义节点二进制、第三方节点整包。
- 凭据、API Key、模型渠道配置、会话历史、生成图片。
- 第三方提示词库原文。
